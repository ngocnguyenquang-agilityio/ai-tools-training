# Code style

- Read the surrounding code first and match its naming, idiom, formatting and comment density.
- Name things for what they mean, not how they are built. Avoid abbreviations.
- Comment only the why, never the what. No commented-out code.
- Keep functions small and single-purpose. Prefer deleting code over adding abstractions.
- Do not add error handling, fallbacks or config for cases that cannot happen.
